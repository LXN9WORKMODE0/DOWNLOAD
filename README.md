## 五组清单

| 组名与命令参数 | 产品层次 | 完整字段清单 |
|---|---|---|
| 水动力 hydrodynamics | 大气单层 | `tp 2t 2d 10u 10v ssrd strd sp tcc` |
| 流域水文 hydrology | 大气与陆面单层 | `tp sf 2t 2d 10u 10v sp ssrd strd e sro ssro sd swvl1 swvl2 swvl3 swvl4` |
| 新能源 energy | 近地面、100 米风和云辐射 | `100u 100v 10u 10v 2t 2d sp ssrd fdir tcc lcc mcc hcc` |
| 天气 weather | 大气单层 | `tp 2t 2d 10u 10v sp msl tcc tcwv` |
| 天气 weather | 850、700、500、200 hPa，每层相同 | `gh t u v q` |
| 海运 shipping | 大气单层 | `10u 10v msl vis` |
| 海运 shipping | 海浪单层 | `swh mwd mwp pp1d shww mdww mpww shts mdts mpts` |

- 水动力的九项依次是总降水、2 米气温、2 米露点、10 米纬向与经向风、地表向下短波与长波辐射、地面气压、总云量。
- 流域水文另关注降雪水当量 sf、总蒸发 e、地表径流 sro、地下径流 ssro、积雪水当量 sd 和四层土壤体积含水量 swvl1–4。径流分量单位为水深，转换为断面流量需要汇流计算。累计量按原窗口、单位和符号处理。
- 天气组用海平面气压 msl 和整层水汽 tcwv 配合地面场；高空为位势高度 gh、温度 t、风分量 u/v、比湿 q。低层风湿诊断水汽输送，500 hPa 高度刻画槽脊，200 hPa 风分析高空急流。山地诊断用地面气压筛掉地下等压面。
- 新能源组保存轮毂附近的 100 米风分量、地表总向下短波 ssrd、地表水平面直射太阳辐射 fdir，以及总云量 tcc 和低、中、高云量 lcc/mcc/hcc。fdir 是水平面直射分量，光伏应用时区分于法向直射辐照度。
- 海运组保留 10 米风、海平面气压和能见度 vis。海浪按“高度、方向、周期”分开：混合浪 swh/mwd/mwp，谱峰周期 pp1d；风浪 shww/mdww/mpww；总涌浪 shts/mdts/mpts。海浪格点保留海陆掩膜和缺测，大气与海浪均采用全球 0.25° 网格，90°N–90°S、0–359.75°E，经度接缝不重复；海浪场有效范围取决于模式海域。

## 取到每次起报的业务终点

2024-11-12 06 UTC 起实施 IFS 49r1。对所选 00/12 UTC 的大气确定性和 WAM 确定性预报，2024-11-12 00 UTC 及此前取到 +240 h，2024-11-12 12 UTC 及此后取到 +360 h。保留原来的输出密度：0–72 h 每 3 h，从 +78 h 起每 6 h。每次起报分别有 53 或 73 个计划时效。2024 年 633 次旧制起报和 99 次新制起报归入同一起报年。跨升级点分开请求，年度末的有效时间可以进入次年。

上述上限是业务产品时效，目标字段在账户档案中的实际返回覆盖须经 GRIB 消息核验。累计字段的 +0 h 按返回情况保留。缺少任何要求的正时效、层次或起报会阻止该包标为完整。第 11–15 天可单独用早年的中期集合研究；次季节与季节预报有自己的起报、成员和统计窗口，需另立清单。

## 使用

从仓库根目录执行以下命令。已验证的环境为 Windows、Python 3.12、ecCodes 2.43.0 和 ECMWF Web API 客户端 1.7.0。

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\run.ps1 plan -Group weather -Year 2024
```

请使用自己的 ECMWF MARS 历史档案账户。可以按客户端标准方式配置用户主目录的 `.ecmwfapirc`，或在本仓库根目录建立同格式的 `.env` JSON 文件，包含 `url`、`key` 和 `email` 三个字段。预览下载计划无需密钥。正式下载前用 `check` 检查网络、凭据配置和解码环境，再运行测速及年度下载。

```powershell
.\run.ps1 check -Group hydrodynamics
.\run.ps1 benchmark -Group hydrodynamics -Year 2024
.\run.ps1 year -Group hydrodynamics -Year 2024
```

以上命令默认保存到 `output`。可为各次运行指定相同的 `-DataRoot` 以复用已核验数据。其他平台可直接运行 `python download.py --help` 查看等价参数。

按水动力、流域水文、新能源、天气、海运顺序逐组推进。默认只运行水动力组；显式指定 `-Group all` 时按上述顺序完成指定年份的各组，每组独立落盘。当前试验只运行水动力组 2024 年。

输出目录为 `full_range/组名/surface|pressure|wave/`；全球海运产品在对应目录再加 `global/`。各包分别保留配置、连接与测速日志以及年度 GRIB 和核验结果。

## 水动力组同磁带试取

每个订单始终包含同一起报全部九个要素和全部计划时效。在 2 月（+240 h）和 12 月（+360 h）各做一次单起报对照及一次尝试扩大批量的试取，两轮变换先后顺序，使用不同日期。每组条件只测一个订单。最多四个数据订单，任何时刻本进程仅等待一个在途请求；实际完成的样本可在合并全年时复用。

逐年下载先查候选合单（最多 8 个连续起报）的 LIST, OUTPUT=COST。场数符合预期且为 0 带时直接取数。其他情况再查询首起报作基准，按候选上限、4、2、1 回退，已查询的批量在此次选择中复用。首个起报为磁盘在线时只接受 0 带，涉及 1 带时只接受至多 1 带。成本返回缺失或单起报需多带时停止该次试验。目录估算反映查询时的存储状态，数据位置和排队策略可能变化。年度入口对新批次执行同样的选择，-Batch 指定候选上限。

每轮至多 5 个目录请求；整个试验上限为 10 个目录请求加 4 个数据订单，一笔完成再提交下一笔。原始成本在 年份/cost/，查询字段数、物理磁带数和目录耗时在 costs.jsonl。timings.jsonl 记录 Web API 等待激活、档案等待和处理、传输与核验时间。report 汇总至 tape_pilot_年份.json，仅在同轮两次实际采用不同批量且预计带数一致时计算每起报等待时间差。另列计入所有目录查询开销的端到端秒/起报。日志未观察到激活状态时，独立等待指标留空。两轮观察只供初选，不能由此断定所有日期存在统一最优批量。
逐批与年度核验包括起报、时效、有效时间、字段、等压面层次、网格、累计窗口、重复和缺失。年度归档采用流式拼接，需同时容纳原批次和年度输出。
## 2024 年水动力组实测

四个订单共核验 18 次起报、10,206 个字段，数据总量 1.178 GB。两个时段的单起报和合单均由 MARS 目录报告为 0 张磁带。

| 时段 | 时效上限 | 单起报（秒/起报） | 8 起报合单（秒/起报） |
|---|---:|---:|---:|
| 2 月 | +240 h | 158.032 | 111.488 |
| 12 月 | +360 h | 177.610 | 204.828 |

用时包含目录查询、服务端处理、传输与本地核验。每种组合在每个时段各测一次，2 和 4 起报未单独计时。上述实测使用先查单起报的旧顺序。发布版已改为先查合单；按这四单的旧日志，2 月和 12 月的合单各可省一次目录查询（36.328 和 148.953 秒）。新顺序的端到端耗时尚待重新实测。

部分 ECMWF GRIB1 表 128 的降水和辐射场只编码预报端点。脚本保留原始字段，计算时段降水或辐射通量时须结合产品累计定义解释窗口。
