# 登记一项下载任务

从[下载任务总表](tasks/README.md)开始。收到明确的下载指令时先登记，即使尚未提交第一个请求，也能查到已经安排过什么。

## 一次指令怎样入账

1. **查重。** 用产品及版本、区域与网格、日期、变量、起报、时效、成员和累计窗口比对已有任务。再看[资产索引](../catalog/assets.csv)及[研究库存](../catalog/research/README.md)中的覆盖、存储代号与核验依据。记录哪些可以复用、哪些尚待核对、哪些确实缺失。有在途订单时先查原订单状态。
2. **登记指令。** 一次独立发出的需求在总表中占一行，写明目标、发出日期（可查时填写）、当前状态、关联明细及更新时间。一次要求下载多个产品或年份时，将相应明细 ID 放在同一行。相同指令的重试、补缺或搬盘沿用原记录。来源暂不明确的历史文件先登记为库存。
3. **记录执行与产物。** MARS 五组方案复用[参数](../plan.json)和[组年明细](../catalog/tasks.csv)。其他来源复用[项目和产品索引](../catalog/research/index.json)，在现有记录文件的 `tasks` 中写目标、进度和缺口，在 `assets` 中写实际副本；新记录文件可复制[示例](../templates/research-client.json)。设备代号用于找到执行快照或数据盘。同一 ECMWF 账户的下载请求按串行安排，恢复前先核对该账户的未完成请求。
4. **同步结果和经验。** 有新进度时更新原总表行中的时间、状态及明细链接。在明细中保留计数单位、实际覆盖、缺口、存储代号和相对目录。把验证过的配置写入[数据源说明](data-sources.md)、[参数表](parameters.json)或单项说明，注明适用范围、试过的参数及实际效果。运行中、暂停、完成分别以执行快照、暂停记录、目标范围的验收结果为依据。

## 可复制的登记内容

```text
任务名称、发出日期、原始目标或来源：
产品、区域、时间、变量及预报维度：
已有任务或副本、可复用范围、需要补取的范围：
执行状态、快照日期、进度与计数单位：
存储代号、相对目录、核验依据：
参数配置或代码入口、试过的设置及效果：
```

字段可以引用已有配置或回执。初次入账时未知的内容写“待确认”，待有证据再补。公开记录使用存储代号；绝对路径、账号凭据、订单号、原始文件与续跑状态保存在本机。

## 核对记录

从仓库根目录执行 `python catalog.py validate` 检查研究目录引用。用 `python catalog.py locate --client workstation-fc01 --task ifs-ens-2025` 查找研究任务的已登记副本；MARS 年度资产用 `python catalog.py locate --task hydrodynamics-2024`。这些查询核对目录和位置，产品完整性依各任务的验收记录判断。
